## 三、关键设计变更

### 3.1 数据库外键变更

**原计划（已废弃）：**
```sql
practice_record_id UUID REFERENCES practice_records ON DELETE SET NULL
```

**最终方案（采用）：**
```sql
practice_record_id UUID REFERENCES practice_records ON DELETE CASCADE
```

**原因：** 记录删除时照片一起删除，符合业务逻辑

### 3.2 上传安全方案变更

**原计划（已废弃）：** STS 临时凭证

**最终方案（采用）：** 预签名 URL

**对比：**
| 方案 | 复杂度 | 安全性 | 维护成本 |
|------|--------|--------|----------|
| STS 凭证 | 高 | 高 | 高 |
| 预签名 URL | 低 | 高 | 低 |

**预签名 URL 流程：**
```
前端 → 请求预签名 URL → 后端生成（带过期时间）→ 前端 PUT 上传 → OSS
```

### 3.3 限额约束设计

**约束条件：**
```sql
CONSTRAINT user_daily_upload_limit
    UNIQUE (user_id, DATE_TRUNC('day', uploaded_at))
    WHERE deleted_at IS NULL
```

**行为：**
- 每天只能有 1 张未删除的照片
- 删除后（设置 deleted_at）可以再上传
- 用户始终只有 1 张有效照片，无法突破限额

## 五、环境变量清单

| 变量名 | 开发必需 | 生产必需 | 风险等级 | 泄露后果 |
|--------|----------|----------|----------|----------|
| `OSS_ACCESS_KEY_ID` | ✅ | ✅ | **HIGH** | 阿里云账号被盗，高额账单 |
| `OSS_ACCESS_KEY_SECRET` | ✅ | ✅ | **HIGH** | 同上 |
| `OSS_BUCKET` | ✅ | ✅ | LOW | 公开无风险 |
| `OSS_ENDPOINT` | ✅ | ✅ | LOW | 公开无风险 |
| `OSS_REGION` | ✅ | ✅ | LOW | 公开无风险 |

**开发配置（.env.local）：**
```bash
OSS_ACCESS_KEY_ID=your_access_key_id
OSS_ACCESS_KEY_SECRET=your_access_key_secret
OSS_BUCKET=ashtanga-app-photos-dev
OSS_ENDPOINT=oss-cn-beijing.aliyuncs.com
OSS_REGION=cn-beijing
```

**安全建议：**
1. 开发环境使用独立的 dev Bucket
2. AccessKey 定期轮换（90 天）
3. 启用阿里云 CloudTrail 日志
4. 不要将 `.env.local` 提交到 git

## 七、风险与注意事项

### 7.1 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| OSS 凭证泄露 | 高额账单 | 使用预签名 URL，限制过期时间；定期轮换凭证 |
| 跨域配置错误 | 上传失败 | 配置 OSS CORS，允许前端域名 |
| 数据库约束冲突 | 用户无法上传 | 软删除时正确处理唯一约束 |
| 照片展示性能 | 时光轴加载慢 | 使用 OSS 图片处理服务生成缩略图 |

### 7.2 业务风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 用户误以为删除后永久丢失 | 客服压力 | 删除提示文案明确说明"可重新上传" |
| 免费用户限额过严 | 用户流失 | MVP 后根据数据调整限额策略 |
| 照片审核合规 | 法律风险 | 后续考虑接入内容审核服务 |
