# `/practice` 首屏 JavaScript 基线

## 固定口径

首屏 JavaScript 指生产版 `/practice` HTML 直接引用的 `/_next/static/*.js`。脚本按文件内容统计原始字节，并用 Node.js `gzipSync(..., { level: 9 })` 计算统一 gzip 字节；不使用服务器压缩头或浏览器缓存值。

重复测量：

```powershell
npm.cmd run build
npm.cmd run measure:initial-js
```

`scripts/measure-initial-js.mjs` 会自行启动临时生产服务器、请求页面、统计脚本并关闭服务器。可用 `--route`、`--port`、`--json` 调整路由、端口和输出格式。

## 2026-06-21 阶段 4 基线与结果

| 检查点 | 脚本数 | 原始大小 | gzip 大小 | 相对初始基线 |
|---|---:|---:|---:|---:|
| 修复邀请常量前 | 17 | 1436.5 KiB | 427.9 KiB | 基线 |
| 邀请常量移出弹窗模块后 | 17 | 1432.7 KiB | 426.5 KiB | -0.3% |
| Mixpanel 改为空闲期异步加载后 | 16 | 1112.6 KiB | 333.8 KiB | **-22.0%** |
| 调试日志采集拆分后 | 16 | 1113.8 KiB | 334.1 KiB | **-21.9%** |

结论：阶段 4 的首屏 JS 相对下降至少 20% 已达到；调试日志拆分后的 0.3 KiB gzip 波动不构成性能回退。最大的 Mixpanel 代码仍保留为独立异步 chunk（构建时 328,233 字节），只是退出 HTML 直接引用清单并延迟到浏览器空闲期加载；这降低首屏解析与水合成本，不代表整个会话永远少下载这些字节。

动态弹窗检查：邀请弹窗正文只存在于非首屏 chunk；页面改从 `lib/invite-version.ts` 读取版本号，源码回归测试禁止重新静态导入弹窗模块。

历史说明：尝试从阶段 4 前提交 `9904705` 建立旧构建时，Next.js 16 Turbopack 拒绝临时项目复用工作区外的 `node_modules`。没有用不同 bundler 或伪造旧值；本表采用同一当前构建链中优化前后连续测得的数据。

## 当前边界

- 该口径衡量 HTML 直接加载的首屏脚本，不统计用户稍后切换 Tab、打开弹窗或浏览器空闲期加载的异步 chunk。
- 每次比较必须先重新生产构建，并保持 Node、Next.js、依赖锁文件和路由一致。
- 阶段 4 仍需把 `app/practice/page.tsx` 从 1829 行继续降到 800–1200 行；性能门槛通过不等于阶段整体完成。
