## 一、核心决策汇总

| 序号 | 决策项 | 最终方案 | 理由 |
|------|--------|----------|------|
| 1 | 存储方案 | ✅ OSS 直传（预签名 URL） | 用户已确认可承担成本，国内速度更快 |
| 2 | 限额策略 | ✅ 允许删除后重传 | 用户删除是正常使用，无法真正"刷"照片 |
| 3 | 记录删除 | ✅ CASCADE DELETE | 记录删除时照片一起删除，无需保留 |
| 4 | 组件架构 | ✅ 容器+UI 拆分 | 逻辑与视图分离，易于测试 |

## 三、关键设计变更

### 3.1 数据库外键变更

**原计划（已废弃）：**
```sql
practice_record_id UUID REFERENCES practice_records ON DELETE SET NULL
```

**最终方案（采用）：**
```sql
practice_record_id UUID REFERENCES practice_records ON DELETE CASCADE
```

**原因：** 记录删除时照片一起删除，符合业务逻辑

### 3.2 上传安全方案变更

**原计划（已废弃）：** STS 临时凭证

**最终方案（采用）：** 预签名 URL

**对比：**
| 方案 | 复杂度 | 安全性 | 维护成本 |
|------|--------|--------|----------|
| STS 凭证 | 高 | 高 | 高 |
| 预签名 URL | 低 | 高 | 低 |

**预签名 URL 流程：**
```
前端 → 请求预签名 URL → 后端生成（带过期时间）→ 前端 PUT 上传 → OSS
```

### 3.3 限额约束设计（支持未来扩展至 9 张）

**数据库设计（已预留扩展）：**
```sql
-- 移除 UNIQUE 约束，改用应用层检查
-- 添加 display_order 字段支持排序
CREATE TABLE photos (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    user_id UUID REFERENCES auth.users NOT NULL,
    practice_record_id UUID REFERENCES practice_records ON DELETE CASCADE,
    oss_url TEXT NOT NULL,
    oss_key TEXT NOT NULL,
    file_size BIGINT NOT NULL,
    mime_type TEXT,
    display_order INTEGER DEFAULT 0,  -- 支持未来拖拽排序
    uploaded_at TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now()),
    deleted_at TIMESTAMP WITH TIME ZONE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now())
);

-- 复合索引支持多照片查询和排序
CREATE INDEX idx_photos_record_order ON photos(practice_record_id, display_order) WHERE deleted_at IS NULL;
```

**限额函数（可配置）：**
```sql
-- 支持传入限额参数，当前默认 1，未来可传入 9
can_user_upload_today(user_uuid UUID, max_photos INTEGER DEFAULT 1)
can_record_add_photo(record_uuid UUID, max_per_record INTEGER DEFAULT 1)
```

**当前行为（MVP）：**
- 免费用户每天 1 张/记录
- 删除后可以重新上传

**未来扩展（付费用户）：**
- 每天最多 9 张/记录
- 通过 `display_order` 字段支持拖拽排序

### 7.1 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| OSS 凭证泄露 | 高额账单 | 使用预签名 URL，限制过期时间；定期轮换凭证 |
| 跨域配置错误 | 上传失败 | 配置 OSS CORS，允许前端域名 |
| 数据库约束冲突 | 用户无法上传 | 软删除时正确处理唯一约束 |

### 7.2 业务风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 用户误以为删除后永久丢失 | 客服压力 | 删除提示文案明确说明"可重新上传" |
| 免费用户限额过严 | 用户流失 | MVP 后根据数据调整限额策略 |

- `OSS_BUCKET`

### 12.3 阿里云 OSS 配置步骤

1. 登录阿里云控制台 → OSS → 创建 Bucket
2. Bucket 名称：`ashtanga-app-photos`（生产）或 `ashtanga-app-photos-dev`（开发）
3. 区域：选择国内节点（如华东1 - cn-beijing）
4. 访问权限：私有（私有Bucket + 预签名URL访问）
5. 跨域配置：允许前端域名 PUT 请求

**CORS 配置示例：**
```xml
<CORSConfiguration>
  <CORSRule>
    <AllowedOrigin>*</AllowedOrigin>
    <AllowedMethod>PUT</AllowedMethod>
    <AllowedMethod>GET</AllowedMethod>
    <AllowedHeader>*</AllowedHeader>
    <MaxAgeSeconds>3600</MaxAgeSeconds>
  </CORSRule>
</CORSConfiguration>
```
