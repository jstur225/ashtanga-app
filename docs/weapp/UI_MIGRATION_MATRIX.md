# 网页版到小程序 UI / 功能迁移矩阵

> 更新日期：2026-08-12（Tab1 背景、练习卡片、锁定/自定义态、开始按钮阴影及横向留白已再次按网页版真源对齐；体式图片与导航毛玻璃降级仍待集中真机复验）
> UI 真源：网页版 `/practice`  
> 执行原则：先建立完整地图，再按 Tab 纵向完成 UI 与真实功能；不先制造一整套不可操作的静态页面。
> 文档定位：UI 控件映射清单；开发阶段和唯一下一步以 `DEVELOPMENT_PLAN.md` 为准。

## 为什么不“先画完所有 UI，再统一接功能”

全部静态画完看起来进度很快，但容易产生三类返工：

1. 真实数据的长度、空状态、错误状态与加载状态会改变布局。
2. 微信原生音频、日历、文件、弹窗和底部安全区会改变交互结构。
3. 大量按钮长期不可用，无法及时发现页面层级和入口设计是否正确。

因此采用纵向迁移：

1. 先提取网页版公共设计系统和四入口导航。
2. 完成“今日练习”的网页版视觉与全部核心操作。
3. 完成“觉察日记”的网页版视觉与全部核心操作。
4. 完成“我的”的网页版视觉与全部核心操作。
5. 完成“体式库”的冻结数据、图片、列表和详情同步。
6. 每完成一个入口就真机验收，不把占位按钮带到下一个阶段。
