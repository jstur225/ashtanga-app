# 小程序本地与云端双模式

> 更新日期：2026-07-16  
> 当前阶段：第二阶段代码完成，待一次性真机验收
> 文档定位：本地与同步专项说明；开发顺序以 `DEVELOPMENT_PLAN.md` 为唯一真源。

## 目标结构

```text
页面 / 月历 / 计时器
          ↓
data-repository
    ├─ 游客：微信本地存储
    └─ 登录：账号本地缓存 → Supabase 同步
```

产品原则：

- 不登录也能使用核心练习记录功能。
- 登录用于云端备份、跨设备和与网页版同步，不作为基础功能门槛。
- 游客、账号 A、账号 B 的本机数据必须隔离。
- 首次登录迁移可重试、不得丢数据、不得制造重复记录。

## 2026-07-09 第一阶段进度

### 已完成

- 登录页增加“暂不登录，直接开始练习”。
- 用户选择游客模式后会记住选择，下一次打开直接进入今日练习。
- 游客拥有独立的本机练习记录和练习选项。
- 今日练习和觉察日记不再强制跳转登录页。
- 月历、补录、编辑、四级颜色和软删除同时支持游客本机数据与登录云端数据。
- “我的”页面显示游客身份、本机记录数和登录入口。
- 退出登录后切回游客工作区，不继续显示账号数据。

### 第二阶段已完成

- 游客 records/options/profile/annotations 使用微信 storage；照片选择后复制到 `USER_DATA_PATH`，不再依赖临时路径。
- 游客 records 为空时幂等创建当月 1 日教程觉察笔记；教程仅用于引导，不导出、不进入游客合并和云端同步。
- 登录账号按 `user.id` 使用独立 account workspace，结构化数据和照片操作共用 pending 队列。
- 首次登录检测游客数据并询问是否合并；使用原 UUID 幂等上传，同一账号只提示一次，不自动删除游客备份。
- 记录多设备编辑使用 base/local/remote 更新时间保护，并在日志记录保留本机或云端的决策。
- 照片先持久化，本机记录先可见；账号同步再直传 OSS、保存元数据并回写 URL，失败可重试。

## 本阶段微信开发者工具验收

1. 退出已有账号，点击“暂不登录，直接开始练习”；空仓库的当月 1 日应出现一条教程觉察笔记，重新编译不重复。
2. 打开觉察日记，点击 `+` 补录一条今天的真实记录。
3. 确认今天在月历变绿，统计卡和时光轴出现该记录。
4. 点击时光轴记录，修改文字和色阶，确认刷新后仍然正确。
5. 重新编译或关闭再打开小程序，确认游客记录仍存在。
6. 在“我的”确认显示游客模式和本机记录数量。
7. 删除这条记录，确认月历、统计和时光轴同时消失。
8. 登录已有账号，选择合并游客数据；摘要只计算真实记录，教程不计入；同步归零后网页端应出现真实记录和照片，但不能出现教程。
9. 网页与小程序交替编辑同一记录，再断网新增并恢复同步；不得重复、丢失或用旧版本静默覆盖新版本。

## 下一步

先完成上述一次性真机验收；若失败，从“我的 → 设置 → 数据管理 → 运行日志”复制 JSON，重点检查 `pending_by_entity`、`photos_pending_upload/delete`、`sync.operations`、`sync.recent_logs` 与 `recent_errors`。通过后进入会员真实状态、个人主体允许的支付/激活承接和分享卡照片，不再修改本地/同步底座。
