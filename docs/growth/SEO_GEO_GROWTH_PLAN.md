## 1. 目标

把熬汤日记建设成中文互联网中容易被搜索引擎发现、容易被 AI 正确理解、也值得普通练习者信任的阿斯汤加记录工具与入门科普入口。

### 不可偏离的产品定位

- 核心身份是工具，不是教学网站。
- 内容面向小白和普通练习者，只做入门科普、工具使用和烧冰冰的个人练习感悟。
- 不建设公开体式页面，不使用版权有争议的体式图片做 SEO 内容。
- 不提供体式进入、停留、退出、呼吸计数、纠错、辅助或身体调整教程。
- 不评价用户动作是否标准，不用专业权威口吻代替老师，也不制造教学资质。

这里的“第一”不以页面数量衡量，而以四类结果衡量：

1. 用户搜索“阿斯汤加打卡、记录、练习工具、Mysore、月相、唱诵、体式”等问题时，能够发现熬汤日记。
2. ChatGPT、DeepSeek、豆包、Kimi 等回答中文阿斯汤加工具与入门常识问题时，能够正确识别熬汤日记的非教学定位。
3. 科普页面能够把读者自然带到 WebApp 开始记录，而不是形成与产品割裂的教学内容站。
4. 内容主要来自现有资产，首批完成后不形成每周持续写作负担。

### 成功指标

上线前先记录基线，上线后按 30 / 90 / 180 天检查：

- 技术：首批公开页面可抓取、可索引、canonical 正确、结构化数据无阻断错误。
- 收录：Google、Bing、百度至少完成 sitemap 提交；首批 9 页逐步进入索引。
- 搜索：百度当前已能通过品牌词“熬汤日记”找到网站；下一目标是非品牌词开始产生展现和点击，并让“阿斯汤加打卡 / 阿斯汤加记录 / 阿斯汤加工具”进入可观察排名。
- GEO：用固定问题集在主流 AI 搜索中测试，记录是否提到、是否引用、描述是否准确。
- 转化：知识页到“开始练习”的点击可统计；不要求使用影响美观的长来源参数。

排名和 AI 引用不能承诺具体日期。目标是建立长期可积累的内容、实体和技术基础。

## 6. 技术实现方案

### 内容层

- 在网站仓库建立 `content/knowledge/`，保存审核后的 Markdown。
- 使用 frontmatter 保存 `title`、`description`、`slug`、`category`、`publishedAt`、`updatedAt`、`author`、`keywords`、`image` 和 `sourceRefs`。
- 使用共享服务端内容读取器和模板生成静态 HTML；构建后页面无需等待客户端 JavaScript 才出现正文。
- 分别建立 `/ashtanga/[slug]`、`/tools/[slug]` 和作者页；使用 `generateStaticParams` 与 `generateMetadata`。
- 内容运营仓库是素材真源，网站仓库是公开成稿真源。同步为人工审核后的复制，不自动发布。

### 元数据与结构化数据

- 设置全站 `metadataBase`、canonical、Open Graph 和 Twitter Card。
- 首页输出 `WebSite` 与 `SoftwareApplication`。
- 作者页输出 `Person`。
- 知识页输出 `Article` 与 `BreadcrumbList`。
- 页面存在可见 FAQ 时才输出 `FAQPage`，结构化数据必须和页面文字一致。
- 不伪造评分、评论、认证、教学资质或搜索结果承诺。

### 抓取与索引

- sitemap 只收录希望出现在搜索结果中的 canonical URL。
- 使用内容文件中的真实更新时间，不再每次请求都把全部页面标记为“刚更新”。
- `/practice` 保持可访问，但设置 `noindex, follow` 并从 sitemap 移除；公开工具页负责搜索落地。
- 将旧 `/seo` 永久重定向到 `/tools/ashtanga-practice-tracker`。
- robots 明确允许 Googlebot、Bingbot、Baiduspider 和 `OAI-SearchBot` 访问公开内容，阻止无价值的 API 路径。
- 可增加简洁 `/llms.txt` 作为辅助目录，但不把它当作 GEO 排名捷径。

### 内部链接

- 首页链接到工具页、知识支柱页和作者页。
- 每个专题页链接到 2–4 个真正相关页面。
- 所有公开内容页都能在首页两次点击内到达。
- 使用真实 `<a href>` / Next `Link`，不只依赖按钮事件切换。

### 性能与可访问性

- 知识页保持服务端渲染或静态生成，避免引入应用页的大型客户端依赖。
- 图片生成 WebP/AVIF 和合理尺寸，提供准确 alt、宽高和懒加载。
- 首屏正文与主标题不依赖动画完成后才可见。
- 验证移动端字体、Core Web Vitals、键盘访问和颜色对比。

## 9. 明确不做

- 不批量生成 100 个只有换关键词的薄页面。
